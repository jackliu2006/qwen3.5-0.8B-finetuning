## 🎯 Project Overview

This project demonstrates a complete MLOps pipeline for fine-tuning **Qwen3-0.6B** on automotive domain knowledge using the **[car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge)** hosted on Hugging Face. The dataset contains instruction-output pairs where outputs are generated by both **GPT-5** and **Gemini-3**, enabling comparative analysis of how different teacher models influence student model performance.

The pipeline automatically generates high-quality training data using state-of-the-art LLMs, performs parameter-efficient fine-tuning with LoRA, evaluates models using both lexical and LLM-as-a-Judge metrics, and deploys to production serving endpoints.

### Key Differentiators

- **Dual-Source Training Dataset**: Uses the [car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge) with outputs generated by both GPT-5 and Gemini-3, publicly available on Hugging Face
- **Comparative Model Training**: Trains separate Qwen3-0.6B models on GPT-5 vs. Gemini-3 generated outputs to analyze knowledge transfer characteristics
- **Automated Synthetic Data Generation**: Complete pipeline for generating diverse, high-quality training datasets with minimal manual curation
- **Production-Ready MLOps**: Full integration with MLflow tracking, Databricks Unity Catalog model registry, and automated serving endpoint deployment
- **Comprehensive Evaluation Framework**: Combines traditional metrics (ROUGE, BLEU) with modern LLM-as-a-Judge evaluation for answer correctness, relevance, and faithfulness

## 📊 Dataset: Car Knowledge

**Dataset**: [jackliu2006/car_knowledge](https://huggingface.co/datasets/jackliu2006/car_knowledge)

The training dataset contains automotive domain knowledge with the following structure:

| Column | Description |
|--------|-------------|
| `instruction` | Questions about car models, features, history, performance, and market data |
| `gpt_output` | High-quality answers generated by **GPT-5** |
| `gemini_output` | High-quality answers generated by **Gemini-3** |
| `temperature` | Generation temperature used (0.2) |
| `max_tokens` | Maximum token limit (400) |

### Dataset Characteristics

- **Dual-Source Outputs**: Each instruction has **two reference answers** - one from GPT-5 and one from Gemini-3
- **Domain Coverage**: Mercedes Benz, BMW, Audi, Tesla, and other major automotive brands
- **Knowledge Scope**: Model specifications, historical context, market trends, safety features, performance metrics
- **Quality Assurance**: Generated using structured prompts with Pydantic validation
- **Size**: ~500 instruction-output pairs (expandable)

### Why Dual-Source?

Training separate models on GPT-5 vs. Gemini-3 outputs enables:
1. **Knowledge Transfer Analysis**: Compare how different teacher models influence student model behavior
2. **Robustness Testing**: Identify which teaching style produces more reliable automotive expertise
3. **Ensemble Potential**: Both models can be deployed for consensus-based inference

## ✨ Technical Highlights

### 1. Synthetic Data Generation Pipeline

Creates the [car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge) with dual-source outputs:

**[prepare-dataset/instructions_generator.py](prepare-dataset/instructions_generator.py)**
- Orchestrates GPT-5 and Gemini-3 via LangChain for instruction generation
- Generates domain-specific questions about car models, features, history, and market performance
- Structured output validation using Pydantic schemas
- Automatic upload to [car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge) on Hugging Face Hub
- Configurable batch sizes and temperature settings

**[prepare-dataset/output_generator.py](prepare-dataset/output_generator.py)**
- Generates reference answers using both **GPT-5** and **Gemini-3** for each instruction
- Concurrent generation using ThreadPoolExecutor for 10x speed improvement
- Fault-tolerant batch processing with automatic retry logic
- Progressive upload strategy using Parquet sharding to the [car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge)
- Resume capability: skips already-processed records on restart
- Creates `gpt_output` and `gemini_output` columns for comparative training

**Key Innovation**: Dual-source data generation enables comparative analysis of how different teacher models (GPT-5 vs. Gemini-3) influence student model performance.

### 2. Parameter-Efficient Fine-Tuning

**[train_eval/sft.py](train_eval/sft.py)**
- **Dataset Source**: Loads [car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge) from Hugging Face Hub
- **Dual Model Training**: Trains **two separate Qwen3-0.6B models**:
  - Model 1: Trained on `gpt_output` column (GPT-5 generated answers)
  - Model 2: Trained on `gemini_output` column (Gemini-3 generated answers)
- **LoRA Configuration**: Rank-64 adapters with alpha=16, targeting all linear layers
- **4-bit Quantization**: BitsAndBytes `nf4` quantization with `bfloat16` compute dtype
- **Memory Optimization**: Gradient checkpointing + 4-bit quantization enables training on consumer GPUs
- **MLflow Integration**: Automatic experiment tracking and model registration to Unity Catalog
- **Automated Model Registry**: Checks for existing models and registers only if needed

**Efficiency Gains**:
- ~75% memory reduction vs. full fine-tuning
- Faster iteration cycles (2 epochs complete in hours vs. days)
- Enables experimentation on single GPU infrastructure

### 3. Comprehensive Evaluation Framework

**[train_eval/eval.py](train_eval/eval.py)**

**Lexical Metrics** (via MLflow built-ins):
- ROUGE-1, ROUGE-2, ROUGE-L (overlap-based)
- BLEU score (corpus-level translation quality)
- Token count statistics

**LLM-as-a-Judge Metrics** (custom scorers):
- **Answer Correctness** (1-5 scale): Factual accuracy vs. reference
- **Answer Relevance** (1-5 scale): Response addresses the question
- **Faithfulness** (1-5 scale): Model stays grounded in training data

**Acceptance Thresholds**:
| Metric | Threshold |
|--------|-----------|
| ROUGE-L F1 | ≥ 0.35 |
| BLEU | ≥ 15.0 |
| Answer Correctness | ≥ 3.5/5 |
| Answer Relevance | ≥ 3.5/5 |
| Faithfulness | ≥ 4.0/5 |

**Why This Matters**: Combines traditional NLG metrics with modern semantic evaluation, providing both quantitative benchmarks and qualitative assessment of model behavior.

### 4. Production Deployment

**[train_eval/deploy.py](train_eval/deploy.py)**
- Automated Databricks Model Serving endpoint creation
- Unity Catalog model versioning and lineage tracking
- Force-recreate flag for iterative deployment
- Automatic cleanup of old model versions (keeps 3 most recent)
- Separate endpoints for `gemini3` and `gpt5` models

## 🚀 Getting Started

### Prerequisites

```bash
# Python 3.12+ required
python --version

# Install dependencies with uv (recommended)
pip install uv
uv pip install -e .

# Or use pip/poetry
pip install -r requirements.txt
```

### Environment Configuration

Create a `.env` file with the following variables:

```bash
# LLM API Configuration
NEXUS_BASE_URL=https://your-nexus-endpoint.com
NEXUS_API_KEY=your_api_key_here

# Hugging Face
HF_DATASET=jackliu2006/car_knowledge
HF_API_KEY=your_hf_token

# MLflow + Databricks
MLFLOW_TRACKING_URI=databricks
MLFLOW_REGISTRY_URI=databricks-uc
MLFLOW_EXPERIMENT_NAME=/Users/your-username/qwen3-car-knowledge
MLFLOW_UC_CATALOG=your_catalog
MLFLOW_UC_SCHEMA=your_schema

# Generation Parameters
TOPICS="Mercedes Benz,BMW,Audi,Tesla"
TARGET_DATASET_SIZE=500
GENERATE_BATCH_SIZE=10
TEMPERATURE=0.2
MAX_TOKENS=400
```

### Pipeline Execution

#### Step 1: Generate Training Instructions

```bash
uv run prepare-dataset/instructions_generator.py
```

Generates diverse questions about car models and uploads to the [car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge) on Hugging Face Hub.

#### Step 2: Generate Outputs (Ground Truth)

```bash
uv run prepare-dataset/output_generator.py
```

Uses **GPT-5** and **Gemini-3** to create high-quality answers for each instruction. Each instruction gets two reference outputs (one from each model), which are stored in `gpt_output` and `gemini_output` columns. Supports resume from interruption.

**Output**: Updates the [car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge) with dual-source annotations.

#### Step 3: Fine-Tune Models on Car Knowledge Dataset

```bash
uv run train_eval/sft.py
```

Loads the [car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge) from Hugging Face and trains **two separate Qwen3-0.6B models**:
- **Model 1** (`Qwen_Qwen3_06B_car_knowledge_finetuned_gemini3`): Trained using the `gemini_output` column
- **Model 2** (`Qwen_Qwen3_06B_car_knowledge_finetuned_gpt5`): Trained using the `gpt_output` column

Both models learn from the same instructions but different teacher-generated outputs, enabling comparative analysis.

#### Step 4: Evaluate Models

```bash
uv run train_eval/eval.py
```

Runs comprehensive evaluation suite and logs results to MLflow.

#### Step 5: Deploy to Production

```bash
uv run train_eval/deploy.py
```

Creates serving endpoints in Databricks for real-time inference.

## 📝 Key Learnings

1. **Public Dataset Value**: The [car_knowledge dataset](https://huggingface.co/datasets/jackliu2006/car_knowledge) with dual GPT-5/Gemini-3 outputs enables reproducible research and comparative analysis of teacher model quality
2. **Synthetic Data Quality**: GPT-5 and Gemini-3 generated data produces models that perform comparably to human-annotated datasets for specialized automotive domains
3. **LoRA Effectiveness**: Rank-64 LoRA adapters capture sufficient domain knowledge while maintaining base model capabilities and reducing training costs by 75%
4. **Evaluation is Critical**: LLM-as-a-Judge metrics reveal subtle quality differences between GPT-5 and Gemini-3 trained models that ROUGE/BLEU miss
5. **MLOps Maturity**: Proper experiment tracking with MLflow and model registry from day one accelerates iteration cycles and enables production deployment
